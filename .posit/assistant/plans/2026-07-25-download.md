- **URL Template:** `https://rsf.org/sites/default/files/import_classement/<year>.csv`

- **Output Format:** Individual CSV files named `rwb<year>.csv`

### Decision: Handling Missing Year 2011
**Recommendation:** Keep 2011 completely missing (no imputation)

**Rationale:**
- Aligns with your existing Shiny app approach (all charts already plot without 2011)
- Preserves data integrity — avoids synthetic data contaminating analysis
- Reflects RSF's actual data publishing: the organization transitioned data for the 2011–2012 biennial period differently
- Simpler implementation and maintenance
- Users can understand the gap by inspecting the data
- **Status:** ✅ Approved by user as preferred approach

### Phase 2: Core Functions (R Package)

#### 2.1 Function: `download_rwb_data()`
**File:** `R/download.R`

**Purpose:** Download individual RSF press freedom index CSVs for specified years

**Signature:**
```r
download_rwb_data(years = 2002:2026, output_dir = "data/raw", skip_missing = TRUE)
```

**Behavior:**
- Accept vector of years (default: 2002–2026)
- Skip 2011 by default (`skip_missing = TRUE`)
- Create `output_dir` if it doesn't exist
- Use `curl::curl_download()` or `readr::read_csv()` with URL directly
- Name files as `rwb<year>.csv`
- Include error handling (network issues, 404s)
- Return invisibly: list of downloaded files with success status
- Include progress messages (which files were downloaded)

**Error Handling:**
- Log failed downloads but continue with others
- Warn user about any connection/permission issues
- Validate year inputs (4-digit integers, reasonable range)

#### 2.2 Function: `combine_rwb_data()`
**File:** `R/combine.R`

**Purpose:** Combine individual RSF CSV files into a single tidy data frame with ISO 3166 country codes

**Signature:**
```r
combine_rwb_data(
  input_dir = "data/raw", 
  output_file = "data/processed/rwb_combined.rds",
  add_iso_codes = TRUE
)
```

**Behavior:**
- Read all `rwb*.csv` files from `input_dir`
- Extract year from filename
- Bind all data frames by rows
- Ensure consistent column names and types across years
- Add `year` column explicitly
- **[NEW] Add ISO 3166 country codes:**
  - Use `countrycode::countrycode()` to map country names to ISO codes
  - Map to both ISO 3 (3-letter, e.g., "USA") and ISO 2 (2-letter, e.g., "US")
  - Create columns: `iso3` and `iso2`
  - Log any unmapped country names (warnings) for manual review
  - Handle special cases (e.g., Kosovo, Taiwan, others) with manual lookup table
- Validate data (check for unexpected NAs, duplicates by country-year)
- Save combined data as `.rds` file
- Return the combined data frame invisibly
- Include informative messages (rows read, years processed, countries mapped, unmapped countries, output location)

**Data Quality Checks:**
- Verify column consistency across years
- Check for duplicate country-year combinations
- Report any structural differences (columns added/removed across years)
- Warn if any years are completely empty
- **[NEW] Warn about unmapped country names** (list country names that couldn't be matched to ISO codes)
- **[NEW] Create mapping report** showing all country name → ISO code conversions

**Special Cases Handling:**
- Create internal lookup table in `R/utils.R` for countries not automatically mapped by countrycode
  - E.g., Kosovo (XK), Western Sahara, etc.
  - Document source of mappings (ISO 3166-1, ISO 3166-3)
- Function parameter `special_mappings = get_special_country_mappings()` to allow customization

#### 2.3 Function: `get_special_country_mappings()`
**File:** `R/utils.R`

**Purpose:** Provide manual ISO code mappings for countries not in standard countrycode library

**Signature:**
```r
get_special_country_mappings()
```

**Return Value:** Named character vector with country names as names and ISO 3 codes as values
```r
c(
  "Kosovo" = "XKX",
  "Western Sahara" = "ESH",  # or custom code
  # ... other special cases specific to RSF data
)
```

**Behavior:**
- Return a lookup table for edge cases
- Document source of each mapping (ISO 3166-1 alpha-3, custom codes, etc.)
- Include comments about why mapping is needed
- Can be extended by user by modifying this function or passing custom mappings to `combine_rwb_data()`

#### 2.4 Function: `get_years_to_download()`
**File:** `R/utils.R`

**Purpose:** Helper to determine which years need downloading (for updates)

**Signature:**
```r
get_years_to_download(input_dir = "data/raw", all_years = 2002:2026)
```

**Behavior:**
- Compare files in `input_dir` against `all_years` list
- Return vector of years that don't have corresponding CSV files
- Automatically exclude 2011
- Useful for incremental updates (e.g., when new year becomes available)

#### 2.5 Function: `update_rwb_data()`
**File:** `R/download.R` or separate `R/update.R`

**Purpose:** Convenience function for annual updates

**Signature:**
```r
update_rwb_data(new_years = NULL, recombine = TRUE)
```

**Behavior:**
- If `new_years = NULL`: auto-detect missing years via `get_years_to_download()`
- Download specified/detected years
- If `recombine = TRUE`: automatically call `combine_rwb_data()` to regenerate RDS
- Return confirmation message with summary (years added, total rows in combined data)

### Phase 3: Targets Pipeline

#### 3.1 Create `_targets.R`
**File:** `_targets.R` at package root

**Pipeline Structure:**
```r
# Define which years to download
tar_target(years_to_download, 2002:2026)

tar_target(
  raw_csvs,
  download_rwb_data(years_to_download, output_dir = here::here("data", "raw"))
)

# Combine and process with ISO code mapping
tar_target(
  rwb_combined,
  combine_rwb_data(
    input_dir = here::here("data", "raw"),
    output_file = here::here("data", "processed", "rwb_combined.rds"),
    add_iso_codes = TRUE,
    special_mappings = get_special_country_mappings()
  ),
  format = "file"
)
```

**Targets Features:**
- Use `tar_load()` to load results in R session
- Use `tar_make()` to run entire pipeline
- Automatic dependency tracking (re-run only if inputs change)
- Useful for updates: modify `years_to_download` target and re-run
- ISO code mapping automatically included in pipeline

## Technical Decisions

### Missing Year (2011)
- ✅ **Keep missing** (no imputation)
- Filter out 2011 in `download_rwb_data()` using `skip_missing = TRUE` default
- Document clearly in function help text

### File Format for Raw Data
- **Store:** CSV files (preserves raw data, lightweight, version-control friendly)
- **Reason:** Easy to audit source data, can be version-controlled

### File Format for Combined Data
- **Store:** `.rds` file (binary R serialization) ✅
- **Why RDS over QS:**
  - Small file sizes (8–16 kB per year file)
  - No additional package dependency (built-in `base::readRDS()` / `base::saveRDS()`)
  - Sufficient for this use case
  - Preserves R types perfectly
  - Easy to version-control

### Paths
- Use `here::here()` throughout (allows package to be installed anywhere)
- Relative paths work both in development and after installation

### URL Downloading
- Use `readr::read_csv(url)` for simplicity (handles encoding, URL parsing)
- Fallback to `curl::curl_download()` if streaming needed
- Include timeout/retry logic for reliability

### ISO Code Mapping
- **Library:** Use `countrycode::countrycode()` for automated mapping
- **Fallback:** Manual lookup table `get_special_country_mappings()` for edge cases
- **Columns Added:**
  - `iso3`: ISO 3166-1 alpha-3 (e.g., "USA", "DEU", "XKX")
  - `iso2`: ISO 3166-1 alpha-2 (e.g., "US", "DE", "XK")
- **Reporting:** Log unmapped country names for user review and manual fixing
- **Documentation:** Include ISO standard references and special case justifications

## ISO Code Mapping Strategy

### Automated Mapping via countrycode Package
**Default Behavior:**
```r
countrycode::countrycode(
  sourcevar = country_name,
  origin = "country.name",      # RSF uses full country names
  destination = "iso3c",        # e.g., "USA", "DEU"
  warn = TRUE                   # Log unmapped countries
)
```

**Advantages:**
- Handles ~195+ countries automatically
- Well-maintained library
- Handles common aliases and variations

**Expected Unmapped Countries:**
- Kosovo (may appear as "Kosovo", "XK" not standard ISO 3166-1)
- Taiwan (may appear as "Taiwan" or "Chinese Taipei")
- Transnistria (if included)
- Other disputed territories or special administrative regions

### Manual Mapping via `get_special_country_mappings()`
**Implementation:**
```r
get_special_country_mappings <- function() {
  # ISO 3166-3 and unofficial codes
  list(
    "Kosovo" = list(iso3 = "XKX", iso2 = "XK"),
    "Taiwan" = list(iso3 = "TWN", iso2 = "TW"),
    # Document source: ISO 3166-1, ISO 3166-3, or custom standard
  )
}
```

**Approach:**
1. First attempt automatic mapping via countrycode
2. For unmapped countries, check `special_mappings` lookup
3. Log any remaining unmapped countries with warning
4. Provide clear message: "X countries couldn't be mapped; check unmapped_countries attribute"

### Validation & Reporting
**After Mapping:**
- Return data frame with new `iso3` and `iso2` columns
- Attach metadata attribute: `unmapped_countries` (character vector)
- Print summary: "Successfully mapped XXX of YYY country records. Z countries unmapped."
- Document mapping in console output (which countries were mapped, which were special cases)

## Design Philosophy: Raw Data Preparation with ISO Standardization

**Scope of This Implementation:**
- This phase handles **raw data acquisition, minimal aggregation, and ISO standardization**
- File naming (`rwb_*`) clearly signals "raw data" status
- **ISO code matching** is included because it's essential for data interoperability (not a cleaning step)
- No other cleaning, transformation, or derivation happens here
- Downstream data cleaning pipeline will consume `rwb_combined.rds` (with ISO codes) as input

**Rationale:**
- Separates concerns: download/combine/standardize vs. clean/transform
- ISO codes enable linking to other international datasets (World Bank, UN, etc.)
- Preserves audit trail: raw data always available for reference
- Allows independent iteration on cleaning logic
- Easy to re-run data acquisition without re-running cleaning
- ISO standardization is foundational and deterministic (unlike domain-specific cleaning)

**Validation (This Phase):**
- Structural checks (column consistency across years)
- Duplicate detection (country-year combinations)
- Missing year handling (2011 explicitly excluded)
- Data type consistency
- **[NEW] ISO code coverage:** Report countries that couldn't be automatically mapped

**ISO Standardization (This Phase):**
- Automated mapping via `countrycode` package for standard countries
- Manual lookup table for special cases (Kosovo, Taiwan, etc.)
- Clear logging of unmapped countries for user review
- Two columns added: `iso3` and `iso2`

**Cleaning (Next Phase — Not This Implementation):**
- Handling encoding issues in country names
- Imputation of missing values (if any)
- Calculation of derived metrics
- Standardizing other string columns (regions, categories, etc.)
- Export to clean data products
